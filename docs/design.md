# 설계 — upload-fit

승인 2026-10-22. 결정이 바뀌면 코드보다 이 파일을 먼저 고친다.

## 문제
업로드 규격(px·용량·형식)이 사이트마다 다르고, 기존 도구는 규격을 사람이 직접 고르거나 입력해야 한다.
비슷한 확장(Remage, UploadReady)도 규격을 수동으로 입력하는 방식이라 사용자가 3~4명이다.
**차별점: 업로드 칸 근처 안내문을 읽어서 자동으로 맞춘다.**

## 결정
| 항목 | 결정 | 포기한 대안 |
|---|---|---|
| 규격 감지 | 업로드 칸 주변 텍스트를 정규식으로 파싱하고, 확인 카드로 사용자 승인을 받음 | LLM 추출 (API 키·비용·페이지 내용 외부 전송), 사이트별 프리셋만 사용 (Remage와 같아짐) |
| 안내문 없는 사이트 | hostname 기준 프리셋을 보조로 사용. 필요한지는 0단계 결과를 보고 확정 | — |
| 파일 바꿔치기 | `window` capture 단계 `change` → `stopImmediatePropagation` → 변환 → `DataTransfer`로 `input.files` 교체 → `change` 다시 디스패치 | input 엘리먼트 교체 (React/Angular ref가 깨짐) |
| 스택 | MV3, 바닐라 JS, 빌드 도구·의존성 없음 | WXT (파일이 10개를 넘거나 popup이 생기면 이전) |
| 규격 객체 형태 | `{ sizes: [[w,h],…], minSide, maxSide, ratios: [[w,h],…], maxBytes, formats: ["jpeg","png",…] }` — sizes는 허용 크기 목록 (ASC는 기기당 여러 개) — 문구에 나온 키만 채운다. 규격이 하나도 없으면 `null` | — |
| 용량 단위 | KB·MB는 1000 단위 | 1024 단위 (사이트가 1000 단위로 검사하면 한도를 넘어 거부됨) |
| 모호한 `A X B` | 같은 문구의 비율과 모순되거나 "사이"가 붙으면 크기가 아니라 변 범위 (`minSide`/`maxSide`) | — |
| 규격 찾는 기준점 | input이 아니라 **사용자가 마지막으로 클릭한 업로드 트리거** 주변 | input 주변 (Play Console은 input이 공용 패널 안에 있어서 실패) |

## 단계
- [ ] **0. 샘플 수집** — 대상 사이트의 업로드 칸 주변 원문을 `spec.test.js` 케이스로 옮긴다 (기대 규격 포함, 이 시점엔 실패가 정상).
  완료: 8곳 이상 케이스 수록, Play Console·ASC에 규격 문구가 있는지 확정해서 아래 "확인된 사실"에 기록
- [ ] **1. `spec.js` 파서** — 텍스트 → 규격 객체.
  완료: `node --test` 통과
- [ ] **2. 가로채기 패스스루** — `change`를 잡아서 같은 파일을 다시 넣기만 한다.
  완료: Play Console·ASC·로컬 테스트 페이지에서 업로드가 평소와 같고, 페이지 `change` 핸들러가 1회만 호출됨
- [ ] **3. 규격 위치 찾기** — 기준점 = 사용자가 마지막으로 클릭한 요소 (capture 단계 `click` 기록). 기준점에서 조상으로 올라가며 텍스트에 규격이 처음 나오는 곳을 채택. 기준점이 없으면 input의 `label[for]`·`aria-describedby`·조상 텍스트, 마지막 폴백은 페이지 안에 규격 문구가 딱 하나일 때.
  완료: 로컬 테스트 페이지(공용 패널 구조 재현 포함)에서 슬롯별로 올바른 규격이 찍히고, 규격 없는 페이지는 `null`
- [ ] **4. `convert.js`** — 리사이즈, cover/contain, 포맷 변환, 품질 이진탐색으로 용량 맞춤, 알파 평탄화, EXIF 회전, 다중 파일.
  완료: `test.html`에서 결과물의 px·bytes·type이 규격과 일치
- [ ] **5. 확인 카드** (Shadow DOM) — "감지: 1320×2868 PNG ≤8MB · [자르기/여백] · [적용] [원본]".
  완료: Play Console에 1080×2340 캡처 → 적용 → 규격 에러 없이 업로드
- [ ] **6. 프리셋 폴백** (0단계에서 필요하다고 확정될 때만).
  완료: ASC 6.9" 슬롯에 1170×2532 → 1320×2868로 변환되어 수락

## MVP에서 빼는 것
드래그앤드롭 업로드 (`drop`의 `dataTransfer.files`는 읽기 전용), HEIC (Chrome이 디코딩 못 함), LLM 파서, 설정 팝업, 웹스토어 배포

## 리스크 — 아직 가정
- ASC는 업로드 칸 근처에 규격 문구가 없을 것 → 0단계에서 확인 (팀원 계정이라 공개 자료로)
- 프레임워크가 합성 `change` 이벤트를 받을 것 → 2단계에서 확인 (Play Console은 Angular)
- canvas의 PNG 출력은 항상 RGBA라서 Apple이 알파 채널로 거부할 수 있음 → 4단계에서 확인
- cm 규격은 DPI를 가정해야 함 → 비율로만 쓰고, px는 사이트가 명시할 때만 신뢰
- closed shadow DOM 안의 input은 보이지 않음

## 수동 검증 체크리스트
- [ ] Play Console: 1080×2340 (2:1 초과) 캡처 → 여백 모드 → 수락
- [ ] ASC: 1170×2532 → 6.9" 슬롯 → 알파 에러 없이 수락
- [ ] 토익: 3000×4000 폰 사진 → 3:4 crop, 용량 이하 jpg → 수락
- [ ] 규격 문구 없는 사이트 → 카드 안 뜨고 원본 그대로
- [ ] PDF 등 이미지 아닌 파일 → 손대지 않음
- [ ] `multiple` 5장 → 전부 변환, 순서 유지
- [ ] 세로로 찍은 아이폰 사진 → 옆으로 눕지 않음
- [ ] 확인 카드에서 "원본" → 원본 정상 업로드
- [ ] react-dropzone 쓰는 사이트 → onChange 1회만 호출

## 확인된 사실
단계를 진행하면서 위 "가정"을 확인되는 대로 여기로 옮긴다.

**Play Console 기본 스토어 등록정보 (2026-10-22, 실제 화면)**
- 규격 문구는 슬롯마다 본문에 있다 (아이콘·그래픽 이미지·휴대전화·7/10인치 태블릿·데스크톱·XR). 원문은 `spec.test.js`.
- 페이지 처음엔 `input[type=file]`이 없다. "애셋 추가" → 오른쪽 **애셋 라이브러리 패널**이 열리고, 그 하단 `simple-uploader` 안에 input 하나가 생긴다. 모든 슬롯이 이 input 하나를 공유한다.
- 패널의 "업로드" 버튼은 그 input에 `click()`을 호출한다. input은 DOM에 연결돼 있고 shadow DOM이 아니다 (`multiple`, `accept=".jpeg,.jpg,.png"`, `display:none`). → `window` capture `change` 방식은 유효.
- 규격 문구(본문)와 input(패널)이 DOM상 멀다 → 3단계 기준점을 "마지막 클릭"으로 바꾼 이유.
- 패널에 "자르기 필요" 필터가 있다 — Play 자체 크롭 기능이 있는지는 미확인.
- 슬롯 장수 규칙("2~8장")은 범위 밖. 파서는 무시한다.
